KROK 3. Priorytet, termin i druga strategia (WYMAGANE NA 3.0)
-----------------------------------------------------------------------------
Co zrobić:
  1. W Zlecenie.h dodaj pola: int priorytet (1..5), int termin (deadline). Git
  2. Zrób interfejs strategii — klasę abstrakcyjną, np. IStrategia: GIT
       virtual void dodaj(const Zlecenie&) = 0; GIT
       virtual bool pusta() const = 0; GIT
       virtual Zlecenie pobierz() = 0; GIT
       virtual ~IStrategia() = default; GIT
  3. Dwie implementacje:
       StrategiaFifo  — w środku std::queue<Zlecenie>
       StrategiaHpf   — w środku std::priority_queue<Zlecenie, std::vector<Zlecenie>, KomparatorPriorytetu>
  4. W Symulatorze zamień pole  std::queue<Zlecenie> kolejka_
     na  std::unique_ptr<IStrategia> kolejka_  i podawaj strategię w konstruktorze.
  5. Uruchom obie strategie NA TYCH SAMYCH zleceniach i porównaj wyniki.
Biblioteki:
  <queue>       std::queue, std::priority_queue
  <memory>      std::unique_ptr, std::make_unique
  <tuple>       std::tie — wygodne porównanie kilku pól naraz w komparatorze
Pułapki:
  - Komparator priority_queue zwraca true, gdy pierwszy element jest GORSZY
    (wyjdzie później). Tak samo jak PozniejszeZdarzenie w Zdarzenie.h.
  - Kopiec nie jest stabilny: przy równym priorytecie dorzuć do porównania
    czas nadejścia i id, inaczej kolejność remisów będzie przypadkowa.

Kolejne strategie (na wyższe oceny) to tylko nowe komparatory:
  SJF   — najkrótszy czas realizacji najpierw
  EDF   — najwcześniejszy termin najpierw (na 4.5)
  AGING — priorytet rośnie z czasem czekania (na 4.5). Sztuczka: porównuj
          klucz (nadejscie - priorytet * T); dzięki temu nie trzeba
          przebudowywać kopca, bo kolejność nie zmienia się w czasie.
